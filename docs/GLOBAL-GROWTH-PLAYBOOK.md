# Interface Craft Pro — Global Growth Playbook

This is a practical, ethical launch plan for attracting real users of Interface Craft Pro. It prioritizes qualified trials, useful feedback, repeat usage, and organic discovery over vanity metrics.

## Positioning

**One-line description**

A strategy-led UI/UX and frontend engineering skill for AI coding agents. It helps agents inspect existing products, define coherent design systems, implement responsive interfaces, recreate references from evidence, and verify the result.

**Primary audiences**
1. Frontend developers using Cursor, Claude Code, Codex, and other repository-aware coding agents.
2. Indie hackers and SaaS founders improving product interfaces.
3. UI engineers and design-system practitioners who want repeatable implementation workflows.
4. Agencies building dashboards, admin panels, landing pages, and workflow tools.

**Core promise**

Move from vague "make it look better" prompts to a structured inspect → plan → implement → compare → verify workflow.

Do not claim universal agent compatibility, automatic installation, pixel-perfect output, or guaranteed results. State the actual environment requirements and show real demonstrations.

## First-use experience

Before promoting broadly, make sure a new user can complete these steps without guessing:

1. Understand what the skill does in under 10 seconds.
2. Know whether their coding agent can read repository files.
3. Make `SKILL.md` available to that agent using a documented, supported import mechanism.
4. Give the agent a small, bounded task in an existing project.
5. See a verifiable result and know what the skill did and did not do.
6. Report a setup problem or share the outcome.

**Important:** Do not publish invented installation commands. Add agent-specific commands only after testing them against the current official documentation and a clean environment. Until then, provide the repository URL and a manual fallback: open `SKILL.md`, provide it as project instructions, and keep the repository files accessible for reference links.

## 30-day campaign

### Week 1 — Make the product understandable
- Apply repository description/topics and enable Discussions.
- Shorten the top-of-README path to a clear "Try it in 5 minutes" flow.
- Record one honest demo: baseline screen → task prompt → agent inspection → implemented result → verification.
- Publish one technical post explaining the inspect/plan/implement/verify method.
- Ask 3–5 developer peers to try one narrow task and report setup friction. Do not ask for stars as a condition of feedback.

### Week 2 — Demonstrate specific outcomes
Publish three focused demos:
1. Improve an existing dashboard without changing business logic.
2. Recreate a reference landing page using inspected evidence.
3. Build or refine a reusable design system and accessible component states.

Each demo should include the exact prompt, relevant repository guide, before/after screenshots, environment, what was verified, and known limitations.

### Week 3 — Join conversations
- Answer relevant questions in frontend, AI-coding, design-engineering, and indie-hacker communities.
- Share a useful technique first; link the repo only when it directly helps.
- Publish a short tutorial on reference-driven UI implementation.
- Invite feedback through GitHub Discussions.
- Do not mass-post identical promotional copy or send unsolicited bulk DMs.

### Week 4 — Convert trials into adoption
- Review questions, issue reports, demo completion, and repeat usage.
- Fix the top 3 onboarding problems.
- Publish a transparent "what changed from user feedback" update.
- Ask users who genuinely found it useful to star or share it, without pressure.
- Create one permission-based case study from a real user's workflow.
