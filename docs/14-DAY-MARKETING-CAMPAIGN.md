# Interface Craft Pro — 14-Day Distribution Campaign

This campaign markets the project as it exists today. Do not claim features, integrations, benchmarks, user counts, or outcomes that have not been verified.

## Positioning

**A practical UI/UX engineering skill for AI coding agents.**

It helps an agent approach interface work with a more disciplined process: inspect the project, understand its design language, plan the screen, implement carefully, and review responsiveness and quality.

Primary audience:
- Frontend and full-stack developers using AI coding agents
- Indie hackers building SaaS products
- Developers maintaining React, Next.js, PHP and Laravel applications
- Product designers and design engineers who want more consistent AI-assisted implementation

Primary CTA: Explore the repository, follow the documented setup, try one real task, and report what worked or failed.

Repository: https://github.com/madnan6299/interface-craft-pro

## Message pillars

1. **Better process, not magic** — structured UI work rather than asking an agent to “make it beautiful”.
2. **Existing projects matter** — improve the codebase already in front of you instead of assuming every task starts from a blank template.
3. **Reference-led implementation** — use a visual reference to guide hierarchy, layout, spacing and interaction decisions.
4. **Quality after implementation** — responsive behavior, accessibility and interaction checks are part of the work.
5. **Open feedback loop** — invite developers to test it on a real screen and open specific issues.

## Ready-to-publish LinkedIn launch post

I’ve been working on **Interface Craft Pro** — a UI/UX engineering skill for AI coding agents.

The problem I wanted to address is familiar: asking an AI agent to “make this UI better” often produces a screen that looks acceptable at first glance but misses the product’s design language, layout details, responsive behavior, or interaction quality.

Interface Craft Pro is built around a more deliberate workflow:
- Understand the existing project before changing it
- Plan the interface and its visual hierarchy
- Use references to guide implementation
- Respect the project’s stack and existing patterns
- Review responsive behavior and interface quality

It is intended for developers working on real products — not just one-off landing page demos.

I’m opening it up for developers to explore and test. Try it on one existing screen, then tell me what worked, what was confusing, and what should improve.
