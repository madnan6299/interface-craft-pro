# Example: SaaS Dashboard Task

## Goal
Help an operations user identify what needs attention and take the next action quickly.

## Direction
- Keep workspace and active module context visible.
- Lead with the most actionable operational summary, not decorative metrics.
- Use meaningful labels, timeframes, and status explanations.
- Provide loading, empty, error, and permission-denied states.
- Keep filters and totals in sync and preserve server-side authorization.
- For dense data, favor consistent table alignment and clear scan paths over excessive cards.

## Acceptance
- A user can identify the primary next action without guessing.
- Empty and failed data states are distinguishable.
- Wide tables have a deliberate small-screen strategy.
- No demo values are presented as live data.
- Relevant build/tests and manual checks are reported accurately.
